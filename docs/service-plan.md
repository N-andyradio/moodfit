# 무드핏(MoodFit) 서비스 기획서

> 성별과 오늘의 기분만 고르면, AI가 상의·하의·신발을 골라주는 코디 도우미

## 1. 서비스 개요

| 항목 | 내용 |
|---|---|
| 서비스명 | 무드핏 (MoodFit) |
| 한 줄 소개 | 성별과 오늘의 기분을 고르면 AI가 상의·하의·신발을 추천하는 코디 도우미 |
| 서비스 목적 | 아침마다 "뭐 입지?"를 고민하는 시간을 줄이고, 코디에 자신 없는 사람도 쉽게 옷을 고르게 돕는다 |
| 타겟 사용자 | 코디에 신경 쓰고 싶지 않거나 옷 고르기가 어려운 모든 사람 (성별·연령 무관) |
| 사용자 가치 | 성별과 기분만 고르면 상의·하의·신발 조합과 추천 이유를 바로 받는다 |

## 2. 페이지 구성과 메뉴 이동

한 페이지(`public/index.html`) 안에 3개 섹션을 두는 싱글 페이지 방식이다. 상단 메뉴를 누르면 해당 섹션으로 부드럽게 스크롤한다.

| # | 섹션 | 역할 | 주요 구성 요소 |
|---|---|---|---|
| 1 | 홈 | 서비스 소개와 진입 | 서비스명, 한 줄 소개, "코디 받으러 가기" 버튼 |
| 2 | 코디 추천 | 핵심 AI 기능 | 성별 선택, 기분 선택, "추천 받기" 버튼, 결과 카드, "다시 추천받기" 버튼, 로딩·오류 안내 |
| 3 | 이용 방법 / FAQ | 사용 안내 | 3단계 이용 방법, 자주 묻는 질문 4개 |

- 메뉴: 홈 / 코디 추천 / 이용 방법
- 이동 방식: 메뉴 클릭 시 해당 섹션으로 스크롤 이동 (앵커 링크)
- 화면 너비가 768px보다 좁으면 메뉴를 햄버거 버튼으로 접는다.
- 반응형 기준: 모바일(375px), 태블릿(768px 이상), 데스크톱(1200px 이상)

## 3. 핵심 기능

1. **AI 코디 추천**: 성별과 기분을 고르면 상의, 하의, 신발과 추천 이유 한 줄을 보여준다.
2. **다시 추천받기**: 같은 선택으로 새 코디를 다시 받는다.
3. **상태 안내**: 로딩 중, 입력 누락, 오류, 응답 지연 상황을 문구로 알려준다.
4. **중복 요청 방지**: 요청 중에는 버튼을 비활성화해 불필요한 AI 호출을 막는다.

## 4. AI 기능 설계

### 4-1. 입력

| 입력 항목 | 형태 | 선택지 | 필수 여부 |
|---|---|---|---|
| 성별 | 버튼 선택 | 여성 / 남성 / 상관없음 | 필수 |
| 오늘의 기분 | 버튼 선택 | 신나요 / 평온해요 / 우울해요 / 피곤해요 / 자신감 있어요 | 필수 |

선택형 입력만 쓰기 때문에 자유 입력으로 생기는 이상한 값과 긴 입력이 원천적으로 줄어든다. 서버도 허용 목록으로 한 번 더 검사한다.

### 4-2. 출력

| 출력 항목 | 내용 |
|---|---|
| 상의 (top) | 추천 상의 |
| 하의 (bottom) | 추천 하의 |
| 신발 (shoes) | 추천 신발 |
| 추천 이유 (reason) | 이 조합이 오늘 기분에 어울리는 이유 한 줄 |

서버는 AI에게 top, bottom, shoes, reason 키를 가진 JSON으로만 답하게 요청한다. AI에게는 한국어로, 쉽게 구할 수 있는 흔한 옷 이름으로, 브랜드 이름 없이 추천하도록 요청한다.

### 4-3. 처리 흐름

1. 사용자가 성별과 기분을 고르고 "추천 받기"를 누른다.
2. 화면의 JavaScript가 `fetch('/api/recommend')`로 POST 요청을 보낸다.
3. 서버 함수(`api/recommend.py`)가 요청을 읽고 성별·기분이 허용된 값인지 검사한다.
4. 서버가 환경 변수 `GEMINI_API_KEY`로 Gemini API를 호출한다.
5. 서버가 AI 답이 올바른 JSON이고 네 항목이 모두 있는지 확인한다.
6. 서버가 결과를 JSON으로 화면에 돌려준다.
7. 화면이 결과 카드를 그린다.

API 키는 서버에서만 사용하며 브라우저 코드에는 넣지 않는다.

### 4-4. 실패 처리 기준

서버가 돌려주는 오류 코드는 아래와 같다.

| 코드 | 언제 나오나 | 서버 안내 문구 |
|---|---|---|
| 400 | 성별·기분 누락, 허용 목록에 없는 값, JSON 형식 오류, 요청 본문이 1024바이트 초과 | 성별과 기분을 모두 선택해주세요. 등 |
| 405 | POST가 아닌 방식으로 요청 | POST 요청만 사용할 수 있어요. |
| 429 | Gemini 사용 한도 초과 | 요청이 많아 잠시 쉬고 있어요. 잠시 후 다시 시도해주세요. |
| 500 | `GEMINI_API_KEY` 없음, Gemini가 12초 안에 응답하지 않음, 그 밖의 Gemini 호출 오류, 예상 못 한 오류 | 서버 설정에 문제가 있어요 / AI 응답이 늦어지고 있어요 / 코디 추천 중 문제가 생겼어요 (모두 "잠시 후 다시 시도해주세요." 포함) |
| 502 | AI 답이 비었거나, JSON이 아니거나, 필요한 항목이 빠짐 | AI가 올바른 답을 주지 않았어요. 다시 시도해주세요. |

사용자 화면에는 아래 문구가 나온다.

| 상황 | 화면 안내 문구 |
|---|---|
| 성별 또는 기분을 고르지 않고 "추천 받기" (서버에 요청하지 않음) | 성별과 기분을 선택해주세요. |
| 응답을 기다리는 중 | 코디를 고르는 중이에요... (로딩 표시) |
| 서버가 오류 코드를 돌려줌 (400, 429, 500, 502 등) | 잠시 후 다시 시도해주세요. |
| 서버에 연결할 수 없음 | 잠시 후 다시 시도해주세요. |
| 응답에 top·bottom·shoes·reason 중 빠진 값이 있음 | 잠시 후 다시 시도해주세요. |
| 15초 안에 응답이 없어 요청을 중단함 | 응답이 늦어지고 있어요. 다시 시도해주세요. |

- 시간 제한: 서버는 AI 호출 전체를 12초로 제한하고 자동 재시도를 하지 않는다. 화면은 15초에 요청을 끊는다. 서버가 먼저 응답하도록 서버 제한을 더 짧게 맞췄다.
- 오류 응답에는 미리 정한 안내 문구만 넣고 API 키나 내부 오류 내용은 넣지 않는다.
- 서버 로그에는 오류 종류와 상태 번호만 남긴다.

## 6. 배포와 환경 변수

- GitHub 저장소를 Vercel 프로젝트에 연결하면, `main` 브랜치에 push할 때마다 자동으로 배포된다.
- 환경 변수 `GEMINI_API_KEY`는 필수다. 로컬은 `.env` 파일에, 배포는 Vercel의 Settings > Environment Variables에 등록한다.
- 환경 변수 `GEMINI_MODEL`은 선택이다. 비워 두면 코드의 기본 모델을 쓴다.
- 환경 변수를 추가하거나 바꾼 뒤에는 재배포해야 적용된다.
- 누구나 접속하려면 Vercel의 Deployment Protection에서 Vercel Authentication을 꺼야 한다.
- API 키는 코드, README, 스크린샷에 노출하지 않는다. `.env`와 `.env.local`은 `.gitignore`에 등록해 GitHub에 올라가지 않게 했다.

## 8. 배포 과정에서 겪은 문제와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| `vercel dev`에서 `NO_RESPONSE_FROM_FUNCTION`, "No python entrypoint found" | Vercel이 Python 시작점을 찾지 못함 | `pyproject.toml`에 `[tool.vercel]` entrypoint 추가 |
| "Could not determine the application interface" | 서버 함수가 `handler` 클래스 방식이라 WSGI/ASGI 형식이 아님 | 요청 처리 부분을 WSGI 방식 `app`으로 교체하고 entrypoint를 `api.recommend:app`으로 변경 |
| 로컬 첫 화면이 405 | 모든 주소를 서버 함수가 받음 | 화면 파일을 `public/` 폴더로 이동 |
| 로컬 첫 추천 요청이 실패 (APITimeoutError) | 첫 Gemini 호출이 제한 시간 안에 끝나지 않음 | 다시 시도하면 성공. 시간 초과 시 안내 문구가 나오도록 처리 |
| 배포 빌드 오류: "No `project` table found" | `pyproject.toml`에 `[project]` 항목이 없음 | 이름·버전·Python 버전·의존성을 담은 `[project]` 추가 |
| 배포 빌드 오류: "Error while parsing config file" | `pyproject.toml` 형식 오류 | 파일을 올바른 형식으로 다시 작성하고 push해 재배포 |
| 배포 주소가 Vercel 로그인 화면으로 이동 | Deployment Protection(Vercel Authentication)이 켜져 있음 | 설정에서 보호를 끄고 시크릿 창에서 공개 접속 확인 |

## 9. 범위와 알려진 한계

- 이번 범위에서는 날씨, 기온, 계절을 반영하지 않는다. 계절에 맞지 않는 추천이 나올 수 있다.
- 호출 횟수 제한이 없다. 주소가 공개되면 누구나 추천을 누를 수 있어 Gemini 사용량이 늘 수 있다. 제출 후에는 키를 폐기하거나 환경 변수에서 지울 수 있다.
- Gemini 응답이 가끔 늦거나 실패해 오류 안내가 나올 수 있다. 배포 주소에서 직접 눌러 본 체감으로는 5번에 1번 정도 실패했고, 다시 누르면 대부분 성공했다.
- 보너스 후보: 다크 모드, 추천 결과 저장·공유, 계절 선택 항목 추가
